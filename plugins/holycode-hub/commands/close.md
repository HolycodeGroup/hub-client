---
description: Close a Hub story without delivering it, saying why — a false positive, won't fix, accepted risk, duplicate or cannot reproduce
argument-hint: <key> <resolution> <reason…> [--reason-code X] [--severity-assessment Y] [--duplicate-of KEY]
---
1. Read `.project-management/hub-pointer.md` and take the value of its `**Project ID:**` line.
2. If the file is missing or has no project id, tell the user "No Hub project in this directory — run /holycode-hub:init" and stop. If any Hub call in this command answers 403 `FORBIDDEN_CREDENTIAL_ORG`, this sign-in belongs to a different organisation than this directory's project: show the Hub's message verbatim (it names the organisation), tell the user to sign in to the Hub again and choose that organisation on the Hub's organisation page (reconnect the `holycode-hub` MCP server so its sign-in opens — in Claude Code: `/mcp` → `holycode-hub` → re-authenticate), and stop — never repeat the call or switch to another project. If any Hub result in this command carries `client_outdated`, first tell the user this plugin is outdated — installed `client_outdated.installed`, published `client_outdated.published` — and to run `/holycode-hub:update`, then restart Claude Code; give no other update steps.
3. `$ARGUMENTS` = `<key> <resolution> <reason…>` with optional `--reason-code <CODE>`, `--severity-assessment AGREE|TOO_HIGH|TOO_LOW`, `--duplicate-of <KEY>`. Resolutions: FALSE_POSITIVE, WONT_FIX, ACCEPTED_RISK, DUPLICATE, CANNOT_REPRODUCE. When the resolution is FIXED, stop and say to use /holycode-hub:complete. A code-review story is one whose claim returned `story.code_review` (its `story.origin` is `CODE_REVIEW`; the Hub's board tags it **Code review**) — `--reason-code` and `--severity-assessment` are only for those. When the story is a code-review story and the resolution is FALSE_POSITIVE without `--reason-code`, ask which part of the finding was wrong: NOT_REACHABLE (it can't be reached), ALREADY_MITIGATED (it is already handled elsewhere — name where), MISREAD_CODE (the finding misread the code), INTENDED_BEHAVIOUR, TEST_OR_DEV_CODE, OTHER.
4. Show the closing as one line and ask ONE confirmation. The reason must be honest and specific (≥ 10 characters) — it trains Code Review.
5. Call the `work_close` tool once with `{ "project_id": "<that id>", "story_id": "<key>", "resolution", "reason", "reason_code"?, "severity_assessment"?, "duplicate_of"? }`. On `CONFLICT_CLAIMED_BY_OTHER` say who must release it first; on `CONFLICT_ALREADY_COMPLETED` say it is already done; on `CONFLICT_CLAIM_HELD` (your own claim raced the close) call it once more with the same input. On success (the story is closed), run `node "${CLAUDE_PLUGIN_ROOT}/scripts/story-worktree.mjs" remove --key <key>` and relay it; after a refusal, leave the worktree alone.
6. **Next step:** end your reply with one line that starts with `Next:` — build it from `result.next` exactly as /holycode-hub:complete does: when `result.next.ready` is non-empty, `Next: /holycode-hub:claim <key> — <title>` for its first entry; when it is empty and `result.next.waiting` is not, `Next: nothing is ready yet — <each waiting key> waits on <its blocked_by keys and statuses>`; when both are empty, `Next: /holycode-hub:status to pick another story`. Never pick or suggest a story yourself. Make no further Hub calls for this step.
