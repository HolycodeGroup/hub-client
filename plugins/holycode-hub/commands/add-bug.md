---
description: File a bug into the linked Hub project's backlog, or edit or delete an existing one — authored on the Hub, not a local file
argument-hint: <bug description> | edit <bug-id> <what changes> | delete <bug-id>
---
1. Read `.project-management/hub-pointer.md` and take the value of its `**Project ID:**` line.
2. If the file is missing or has no project id, tell the user "No Hub project in this directory — run /holycode-hub:init" and stop.
3. **Edit mode** — when `$ARGUMENTS` starts with `edit <bug-id>` (a bug is a story row): call the `project_status` tool on the `holycode-hub` MCP server once with `{ "project_id": "<that id>" }` and take that bug's row (title, points, priority, its `version`); build ONLY the changed fields (`title`, `description`, `points`, `priority`) — severity and reproduction steps live in the description, which replaces the stored one wholesale, so write it in full and keep its leading `[SEVERITY]` tag; show a before/after diff and ask ONE confirmation.
4. On yes, call the `project_story_update` tool once with `{ "project_id": "<that id>", "story_id": "<bug-id>", "version": <the fetched version>, ...the changed fields }`; a `409` means the story changed since you read it — re-fetch `project_status` and re-show the diff, never blind-retry; a `422` (`BUSINESS_STORY_CLAIMED` / `BUSINESS_STORY_COMPLETED` / `BUSINESS_PROJECT_ARCHIVED`) means report it and stop — a fixed bug that recurs is a new bug. Report the story_id and new version, then stop.
5. **Delete mode** — when `$ARGUMENTS` starts with `delete <bug-id>`: call the `project_status` tool on the `holycode-hub` MCP server once with `{ "project_id": "<that id>" }` and take that bug's row (id, title and its `version`) — if it is not on the board, report that and stop; show its id and title and ask ONE explicit confirmation (it leaves the status board, estimates and the claim pool; its history is kept). On yes, call the `project_story_delete` tool once with `{ "project_id": "<that id>", "story_id": "<bug-id>", "version": <the fetched version> }`; a `422` `BUSINESS_STORY_HAS_DEPENDENTS` names the stories that depend on it — show those ids and stop (remove the dependency with `edit` first); a `409` means it changed since you read it — re-fetch `project_status` and re-confirm, never blind-retry; any other `422` (`BUSINESS_STORY_CLAIMED` / `BUSINESS_STORY_COMPLETED` / `BUSINESS_PROJECT_ARCHIVED`) means report it and stop. Report the deleted story_id, then stop.
6. **Add mode** (anything else): run `/holycode-hub:guidance bug-report shape` to get the bug shape, then build from `$ARGUMENTS` the input `{ "phase": { "name", "priority" }, "epic": { "name", "priority" }, "bug": { "title", "severity", "description", "priority" } }`; show it to the user for confirmation before writing.
7. Call the `project_bug_add` tool on the `holycode-hub` MCP server exactly once with `{ "project_id": "<that id>", ...the built phase/epic/bug }`.
8. Report the returned story_id / epic_id / phase_id. Make no further Hub calls for this step.
