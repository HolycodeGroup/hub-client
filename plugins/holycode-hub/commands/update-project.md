---
description: Change the linked Hub project's type, stack or story-key prefix, or one repository's own stack — shows the current values and a before/after diff, then asks once
argument-hint: [what to change]
---
1. Read `.project-management/hub-pointer.md` and take the value of its `**Project ID:**` line.
2. If the file is missing or has no project id, tell the user "No Hub project in this directory — run /holycode-hub:init" and stop. If any Hub call in this command answers 403 `FORBIDDEN_CREDENTIAL_ORG`, this sign-in belongs to a different organisation than this directory's project: show the Hub's message verbatim (it names the organisation), tell the user to sign in to the Hub again and choose that organisation on the Hub's organisation page (reconnect the `holycode-hub` MCP server so its sign-in opens — in Claude Code: `/mcp` → `holycode-hub` → re-authenticate), and stop — never repeat the call or switch to another project. If any Hub result in this command carries `client_outdated`, first tell the user this plugin is outdated — installed `client_outdated.installed`, published `client_outdated.published` — and to run `/holycode-hub:update`, then restart Claude Code; give no other update steps.
3. Read the current values: call the `project_status` tool on the `holycode-hub` MCP server once with `{ "project_id": "<that id>" }` and take `result.project.project_type`, `stack`, `story_key_prefix`, `version` and `repositories` (each with its `id`, `url` and own `stack`).
4. Work out the new values from `$ARGUMENTS` (or ask the user what to change — the project type, the project stack, the story-key prefix and/or one repository's own stack). A repository's stack names one repository: this repository (the pointer's `**Repository ID:**` line) unless the user names another by its URL; a project stack change also moves every repository still on the old project stack, so say so in the diff. Show the current values and a before/after diff of ONLY the fields that change, and ask ONE confirmation; when nothing would change, say so and stop.
5. On yes, call the `project_update` tool on the `holycode-hub` MCP server once with `{ "project_id": "<that id>", "version": <the version read in step 3>, ...only the changed fields }` (`project_type`, `stack`, `story_key_prefix`, and `repository: { "id": "<repository id>", "stack": "<new stack>" }` for one repository's stack). A `422` `BUSINESS_REPOSITORY_UNKNOWN` means that repository id is not one of the project's: read `project_status` again and ask which repository was meant. A `409` `CONFLICT_STALE_VERSION` means the project changed since you read it: read it again with `project_status`, re-show the diff against the fresh values and ask again — never retry the same payload blindly. A `422` `BUSINESS_PROJECT_ARCHIVED` (the project is archived) or a `400` naming a field: report the Hub's message and stop. On success report the new values and version. **Next step:** end your reply with one line that starts with `Next:` — `Next: /holycode-hub:status to see the board with the new values`. Make no further Hub calls for this step.
