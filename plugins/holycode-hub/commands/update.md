1. Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/update-plugin.mjs"` and show the developer its report as printed. It refreshes the holycode-hub marketplace, then updates this plugin through the Claude Code CLI (`claude plugin update`), each step with a timeout.
2. When it reports the plugin is already current, say so — nothing needs a restart — and make no Hub call.
3. When it reports an update (`updated <old> → <new>`), bring the framework command cards back for the new version, whose `commands-cache/` starts empty: when the report names `New plugin directory: <dir>`, call the `work_sync` tool on the `holycode-hub` MCP server exactly once with `{ "client_version": "<new>" }` and no `command_cache` (so every card comes back), then pipe the JSON of `result.command_deltas` into `node "${CLAUDE_PLUGIN_ROOT}/scripts/apply-command-deltas.mjs" --cache "<dir>/commands-cache"` (stdin) and report its one-line summary. Then, if `.project-management/hub-pointer.md` exists (this repository is linked), refresh its `AGENTS.md` Hub workflow section from `<dir>/agents/hub-workflow-section.md` exactly as `/holycode-hub:sync-commands` does — replace everything between the `<!-- holycode-hub:start -->` and `<!-- holycode-hub:end -->` markers (create the file, or append the block when the markers are absent), never change text outside them — and report whether `AGENTS.md` was created, refreshed or already current. Write into no other plugin directory. If the step cannot finish — the report says `New plugin directory not found` (then make no Hub call), the Hub is unreachable, the sign-in fails, or the apply script exits non-zero (a refused card) — the update still stands: name the failure and tell the developer to run `/holycode-hub:sync-commands` after the restart.
4. After an update, tell the developer to restart Claude Code once: plugins load only at startup, so the new version and its commands, the synced cards included, appear after the restart — no `/holycode-hub:sync-commands` is needed when step 3 finished.
5. On a non-zero exit of the update script, relay the failed step, its reason and the manual steps the script printed — the only case in which those steps are shown. Never retry in a loop, never edit Claude Code's settings or the plugin cache yourself beyond step 3's sync into the reported directory, and never accept a marketplace-declared install command on the developer's behalf. **Next step:** end your reply with one line that starts with `Next:` — `Next: restart Claude Code, then /holycode-hub:status` — when step 3 could not finish, `Next: restart Claude Code, then /holycode-hub:sync-commands` — or, when nothing was updated, `Next: carry on`. Make no further Hub calls for this step.
