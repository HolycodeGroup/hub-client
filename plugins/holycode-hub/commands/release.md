---
description: Release a claimed Hub story's lease without completing it — return the story to the pool for another developer
argument-hint: <story-key> [decline reason]
---
1. Read `.project-management/hub-pointer.md` and take the value of its `**Project ID:**` line. Then run `node "${CLAUDE_PLUGIN_ROOT}/scripts/story-worktree.mjs" check`: for each story worktree it lists as expired, tell the developer the lease lapsed and offer to re-claim the story (`/holycode-hub:claim <key>`) or keep its branch (`node "${CLAUDE_PLUGIN_ROOT}/scripts/story-worktree.mjs" keep --key <key>`) — never delete one yourself.
2. If the file is missing or has no project id, tell the user "No Hub project in this directory — run /holycode-hub:init" and stop. If any Hub call in this command answers 403 `FORBIDDEN_CREDENTIAL_ORG`, this sign-in belongs to a different organisation than this directory's project: show the Hub's message verbatim (it names the organisation), tell the user to sign in to the Hub again and choose that organisation on the Hub's organisation page (reconnect the `holycode-hub` MCP server so its sign-in opens — in Claude Code: `/mcp` → `holycode-hub` → re-authenticate), and stop — never repeat the call or switch to another project. If any Hub result in this command carries `client_outdated`, first tell the user this plugin is outdated — installed `client_outdated.installed`, published `client_outdated.published` — and to run `/holycode-hub:update`, then restart Claude Code; give no other update steps.
3. First run `node "${CLAUDE_PLUGIN_ROOT}/scripts/effort-capture.mjs" take` — it prints the effort measured since the last report as a JSON array (timestamps, actor and category only; never prompt text or code). When the array is non-empty, add it to the call as `"segments": <that array>` and do NOT send `human_ms` / `ai_ms`; when it prints `[]` or the command fails, use the estimate instead. Also run `node "${CLAUDE_PLUGIN_ROOT}/scripts/effort-capture.mjs" usage` — it prints the tokens this attempt used so far, per model, as a JSON array (counts only, never prompt text); when it is non-empty add it as `"model_usage": <that array>` (omit the field when it prints `[]` or fails). Otherwise estimate the human-vs-AI time split for the work so far (your best estimate in milliseconds — `human_ms` for the human thinking/deciding/reviewing, `ai_ms` for your generating; together ~the elapsed time), then call the `work_release` tool on the `holycode-hub` MCP server exactly once with `{ "project_id": "<that id>", "story_id": "<story key>", "decline_reason": "<reason>", "human_ms": <human estimate>, "ai_ms": <AI estimate> }` — the first `$ARGUMENTS` token is the story key; everything after it is the decline reason (the developer declined the story right after claiming it): send it as `decline_reason` (at most 500 characters) and omit the field when there is none — it is an ESTIMATE, not a measurement; OMIT both fields if you genuinely cannot estimate (never send `0` / `0`).
4. Handle the answer:
   - success → tell the user the lease is released and the story is claimable again by any developer (for a decline, that the reason was recorded); then run `node "${CLAUDE_PLUGIN_ROOT}/scripts/story-worktree.mjs" remove --key <story key>` and relay it — the worktree is removed once its branch is pushed or merged (an untouched branch counts as merged), otherwise it stays and the reason is shown; with `sharedWith` it stays because those stories of the same group still work in it.
   - `FORBIDDEN_CLAIM` → tell the user they do not hold this story's lease (nothing to release — it was never claimed by them, or already released/expired) and stop.
   - any other error → report the code + request id and stop; never work around it.
5. **Next step:** end your reply with one line that starts with `Next:` — build it from `result.next`, in the Hub's order: when `result.next.ready` is non-empty, `Next: /holycode-hub:claim <key> — <title>` for its first entry; when it is empty and `result.next.waiting` is not, `Next: nothing is ready yet — <each waiting key> waits on <its blocked_by keys and statuses>`, adding `/holycode-hub:resolve-questions` when a waiting entry has `open_questions` above 0; when both are empty, `Next: /holycode-hub:status to pick another story`. Never pick or suggest a story yourself. When `result.next` is absent (an older Hub), `Next: /holycode-hub:status to pick another story`. Make no further Hub calls for this step.
