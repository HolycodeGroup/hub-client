---
description: Publish a local Markdown file as a new version of one of the project's documents on the Hub — guarded by the version you read
argument-hint: <document> <file> [story-key]
---
1. Read `.project-management/hub-pointer.md` and take the value of its `**Project ID:**` line.
2. If the file is missing or has no project id, tell the user "No Hub project in this directory — run /holycode-hub:init" and stop. If any Hub call in this command answers 403 `FORBIDDEN_CREDENTIAL_ORG`, this sign-in belongs to a different organisation than this directory's project: show the Hub's message verbatim (it names the organisation), tell the user to sign in to the Hub again and choose that organisation on the Hub's organisation page (reconnect the `holycode-hub` MCP server so its sign-in opens — in Claude Code: `/mcp` → `holycode-hub` → re-authenticate), and stop — never repeat the call or switch to another project. If any Hub result in this command carries `client_outdated`, first tell the user this plugin is outdated — installed `client_outdated.installed`, published `client_outdated.published` — and to run `/holycode-hub:update`, then restart Claude Code; give no other update steps.
3. `$ARGUMENTS` is `<document> <file>` and an optional story key: `<document>` is one of `PRD`, `ARCHITECTURE`, `TECHNICAL_SPEC`, `API_SPEC`, `SCREENS`, `DECISIONS_AND_CONSTRAINTS`, `GLOSSARY`; `<file>` is a local Markdown file. Read the file whole. It must carry no revision table or change log — the history lives on the Hub — so drop one if it has it, and never send source code or secrets.
4. Call the `project_documentation_read` tool on the `holycode-hub` MCP server once with `{ "project_id": "<that id>", "document": "<document>" }` and take `latest_version` as the base (0 when it is null).
5. Call the `project_documentation_update` tool once with `{ "project_id": "<that id>", "document": "<document>", "base_version": <the base>, "content": "<the file>" }`, adding `"story_id": "<story-key>"` when one was given (the version is then that story's, or its bug fix). On `409 CONFLICT_DOCUMENT_STALE` someone published meanwhile: tell the user, show the newer version's changes from a fresh read and stop — never overwrite blindly. On `422 BUSINESS_DOCUMENT_APPEND_ONLY` the document only grows: keep its current text and add to it. On `422 BUSINESS_DOCUMENT_CONTENT_PROTECTED` rephrase the named field.
6. Report the new version number. When `result.held_sections` is not empty, tell the user those sections were written by hand and were kept as they are; the text offered for them is stored as a proposal for a person to review. **Next step:** end your reply with one line that starts with `Next:` — `Next: /holycode-hub:complete <key>` when the version belongs to a claimed story, otherwise `Next: /holycode-hub:status`. Make no further Hub calls for this step.
