---
description: Claim a Hub story for implementation — story text, acceptance criteria, phase context, directive, project rules and command cards, and an 8-hour lease in one call
argument-hint: <story-id>
---
1. Read `.project-management/hub-pointer.md` and take the value of its `**Project ID:**` line.
2. If the file is missing or has no project id, tell the user "No Hub project in this directory — run /holycode-hub:init" and stop.
3. Build `rule_cache`: if `.project-management/rules/.versions.json` exists, send `{ "project": { "<path>": <that entry's version> } }` (versions only — never text or hashes); omit `rule_cache` entirely when the file is missing. Build `command_cache`: if `${CLAUDE_PLUGIN_ROOT}/commands-cache/.manifest.json` exists, take its parsed contents verbatim, else omit it.
4. Call the `work_claim` tool on the `holycode-hub` MCP server exactly once with `{ "project_id": "<that id>", "story_id": "$ARGUMENTS", "rule_cache": <that object, when present>, "command_cache": <that object, when present> }`. The `result` is a JSON object with `story`, `context`, `directive` and `lease`; if it arrives as a text content block, parse that text as JSON first, then read the fields below off it.
5. Pipe the JSON of `result.directive.rule_deltas` into `node "${CLAUDE_PLUGIN_ROOT}/scripts/apply-rule-deltas.mjs" --project-root "$PWD"` (stdin) and report its one-line summary; a non-zero exit means a delta was refused or a project file was skipped as an unsynced local edit (`project.conflicts`) — report it and suggest `/holycode-hub:sync`, never work around it.
6. Pipe the JSON of `result.directive.command_deltas` into `node "${CLAUDE_PLUGIN_ROOT}/scripts/apply-command-deltas.mjs"` (stdin) and report its one-line summary; a non-zero exit means a card was refused — report it, never work around it.
7. Tell the user the lease expiry (`result.lease.expires_at`), that the directive is the knowledge for this step — story text, acceptance criteria, phase context, gate criteria and the `result.directive.guidance` entries (topic-keyed checklists: follow each one during implementation) are in the response — that the project's own rule deltas landed in this repository's `.project-management/rules/`, and the framework command cards in the plugin's `commands-cache/`. If `result.client_outdated` is present, first tell the user this plugin is outdated — installed `result.client_outdated.installed`, published `result.client_outdated.published` — and to update by running `/plugin marketplace update holycode-hub`, then `/plugin uninstall holycode-hub@holycode-hub`, then `/plugin install holycode-hub@holycode-hub`, then restarting Claude Code; an outdated plugin can lack instructions the Hub now expects. Make no further Hub calls for this step.
