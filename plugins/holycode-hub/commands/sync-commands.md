1. Build `command_cache`: if `${CLAUDE_PLUGIN_ROOT}/commands-cache/.manifest.json` exists, take its parsed contents verbatim (hashes only — never text), else omit it. Take `client_version` from the `version` field of `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json` (omit it if that file cannot be read).
2. Call the `work_sync` tool on the `holycode-hub` MCP server exactly once with `{ "command_cache": <that object, when present>, "client_version": "<that version, when present>" }`. No project id and no story id are needed. The `result` is a JSON object with `command_deltas` and, only when this plugin is behind the published version, `client_outdated`; if it arrives as a text content block, parse that text as JSON first, then read the fields below off it.
3. Pipe the JSON of `result.command_deltas` into `node "${CLAUDE_PLUGIN_ROOT}/scripts/apply-command-deltas.mjs"` (stdin) and report its one-line summary; a non-zero exit means a card was refused — report it, never work around it.
4. If any Hub result in this command carries `client_outdated`, first tell the user this plugin is outdated — installed `client_outdated.installed`, published `client_outdated.published` — and to run `/holycode-hub:update`, then restart Claude Code; give no other update steps.
5. If `.project-management/hub-pointer.md` exists (this repository is linked), refresh its `AGENTS.md` Hub workflow section exactly as `/holycode-hub:init` does: copy the contents of `${CLAUDE_PLUGIN_ROOT}/agents/hub-workflow-section.md` into `AGENTS.md` — create the file with that content if missing; if it exists, replace everything between the `<!-- holycode-hub:start -->` and `<!-- holycode-hub:end -->` markers (append the whole block when the markers are absent); never change text outside the markers. Report whether `AGENTS.md` was created, refreshed or already current. Then take the pointer's `**Project ID:**` line. **Repository (HH-476):** when the pointer has no `**Repository ID:**` line, call the `project_status` tool on the `holycode-hub` MCP server once with `{ "project_id": "<that id>", "summary_only": true }` and pipe its JSON result into `node "${CLAUDE_PLUGIN_ROOT}/scripts/pointer-repository.mjs" resolve` (stdin): it compares this checkout's `origin` URL, credentials removed, with `project.repositories` on this machine — the URL is never sent — and adds the line. On `added` report the repository it recorded. On `no-match` (HH-489) ask the developer exactly ONE yes/no question — the answer's `question`, which names this checkout's repository, the project and the proposed kind `proposed_kind` (they may name another kind instead: BACKEND, FRONTEND, MOBILE or SHARED). On yes call the `project_repository_add` tool once with `{ "project_id": "<that id>", "kind": "<the confirmed kind>", "url": "<the answer's url>" }` and then run `node "${CLAUDE_PLUGIN_ROOT}/scripts/pointer-repository.mjs" record --id <the returned repository.id>`, and report the repository added — when it is the project's first repository, its stories without a repository take it. On no, add nothing and carry on without a repository. Never call `project_repository_add` without that yes. `present` and `no-origin` need no word.
6. Tell the user the framework command cards now live in the plugin's `commands-cache/`, and that they must RESTART Claude Code for the new commands to appear (Claude Code registers plugin commands at session start). **Next step:** end your reply with one line that starts with `Next:` — `Next: restart Claude Code, then /holycode-hub:status`. Make no further Hub calls for this step.
