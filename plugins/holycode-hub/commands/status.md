---
description: Show the linked Hub project's live status board
---
1. Read `.project-management/hub-pointer.md` and take the value of its `**Project ID:**` line.
2. If the file is missing or has no project id, tell the user "No Hub project in this directory — run /holycode-hub:init" and stop.
3. Call the `project_status` tool on the `holycode-hub` MCP server exactly once with `{ "project_id": "<that id>" }`.
4. If the Hub answers 403 `FORBIDDEN_RESOURCE`, tell the user the same "No Hub project in this directory — run /holycode-hub:init" message (the pointer names a project this account cannot see) and stop.
5. First show **Ready to claim** from `result.ready`, in the Hub's order: one line per entry with its `key`, `title`, `priority` and `points`, and the command `/holycode-hub:claim <key>` (note that `/holycode-hub:claim` with no argument takes the first one). When `result.ready` is empty, say nothing is ready yet and list each `result.waiting` entry's key with the keys and statuses it is `blocked_by`. Never pick or suggest a story yourself.
6. Then render the board **grouped by phase, then by epic** — never one flat table interleaving phase/epic/story rows. Walk `result.project.phases` in the Hub's returned order; for each phase render a phase heading (`name` + `status`), then its `epics` in order, and under each epic its `stories` as a compact table — each story with its **key** (never the long `id`), title, status, points and `dep_keys` — keeping the phase → epic → story nesting visible (headings or indentation).
7. **At the end of each phase**, render a per-phase progress bar from that phase's own story completion (`phase_completed_stories` = stories with status `COMPLETED` across the phase's epics, `phase_total_stories` = all stories in the phase). Use a fixed 20-character bar: `filled = round(20 * phase_completed_stories / phase_total_stories)` full blocks `█` then the rest `░`, then `round(100 * phase_completed_stories / phase_total_stories)%` and `(phase_completed_stories/phase_total_stories stories)` — e.g. `[██████░░░░░░░░░░░░░░] 30% (3/10 stories)`. A phase with 0 stories renders `[░░░░░░░░░░░░░░░░░░░░] n/a (0 stories)` — never divide by zero.
8. After all phases, render the summary line exactly as returned (OWNER and DEVELOPER receive the same board; points stay in the summary line unchanged). Right after the summary line, render the **project-level** progress bar for the whole project's story completion, derived from the summary counts (`result.summary.completed_stories`, `result.summary.total_stories`): same fixed 20-character bar `filled = round(20 * completed_stories / total_stories)` full blocks `█` then `░`, then `round(100 * completed_stories / total_stories)%` and `(completed_stories/total_stories stories)` — e.g. `[████████░░░░░░░░░░░░] 38% (8/21 stories)`; `total_stories` of 0 renders `[░░░░░░░░░░░░░░░░░░░░] n/a (0 stories)` and never divides by zero. Every bar tracks stories (not points). Make no further Hub calls for this step.
