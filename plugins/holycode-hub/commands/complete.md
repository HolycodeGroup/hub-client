---
description: Mark a claimed Hub story complete — anchor its commit, release the lease, record the completion
argument-hint: <story-key> [commit-sha] [--scope phase <name> | epic <name> | <story-key> …]
---
1. Read `.project-management/hub-pointer.md` and take the value of its `**Project ID:**` line. Then run `node "${CLAUDE_PLUGIN_ROOT}/scripts/story-worktree.mjs" check`: for each story worktree it lists as expired, tell the developer the lease lapsed and offer to re-claim the story (`/holycode-hub:claim <key>`) or keep its branch (`node "${CLAUDE_PLUGIN_ROOT}/scripts/story-worktree.mjs" keep --key <key>`) — never delete one yourself.
2. If the file is missing or has no project id, tell the user "No Hub project in this directory — run /holycode-hub:init" and stop. If any Hub call in this command answers 403 `FORBIDDEN_CREDENTIAL_ORG`, this sign-in belongs to a different organisation than this directory's project: show the Hub's message verbatim (it names the organisation), tell the user to sign in to the Hub again and choose that organisation on the Hub's organisation page (reconnect the `holycode-hub` MCP server so its sign-in opens — in Claude Code: `/mcp` → `holycode-hub` → re-authenticate), and stop — never repeat the call or switch to another project.
3. The first `$ARGUMENTS` token is the story key (e.g. `DHWH-7`; an old story id also works); the optional second is the commit sha — when absent, take the current commit from `git rev-parse HEAD`, and if that fails tell the user "Pass the commit sha: /holycode-hub:complete <story-id> <commit-sha>" and stop. Everything after a `--scope` token (the sha, when given, comes before it) is a standing-order scope: `phase <name>` → `{ "phase": "<name>" }`, `epic <name>` → `{ "epic": "<name>" }`, otherwise the story keys → `{ "stories": [<each key>] }`; send it as `"scope"` on the call below (omit it when there is no `--scope`).
4. First run `node "${CLAUDE_PLUGIN_ROOT}/scripts/effort-capture.mjs" take` — it prints the effort measured since the last report as a JSON array (timestamps, actor and category only; never prompt text or code). When the array is non-empty, add it to the call as `"segments": <that array>` and do NOT send `human_ms` / `ai_ms`; when it prints `[]` or the command fails, use the estimate instead. Otherwise estimate the human-vs-AI time split for this attempt (your best estimate in milliseconds — `human_ms` for the human thinking/deciding/reviewing, `ai_ms` for your generating; together ~the attempt's elapsed time), then call the `work_complete` tool on the `holycode-hub` MCP server exactly once with `{ "project_id": "<that id>", "story_id": "<story id>", "commit_sha": "<that sha>", "human_ms": <human estimate>, "ai_ms": <AI estimate> }` — it is an ESTIMATE, not a measurement; OMIT both fields if you genuinely cannot estimate (never send `0` / `0`).
5. On success report the recorded commit, the completion time, and that the lease is released and the story is now `Completed`. When `result.standing_order` is present, list each `result.standing_order.handed_out` entry (`key — title`) as handed to the user next under the standing order (`/holycode-hub:claim <key>` returns its text), and say how many stories of the scope are still open (`result.standing_order.open`; 0 means the standing order is done). Then ALWAYS end with what comes next, exactly as the Hub returned it in `result.next`: when `result.next.ready` is non-empty, write `Next: <key> — <title>` for its first entry and `Run /holycode-hub:claim <key>` (or `/holycode-hub:claim` with no argument), listing any other ready entries below it; when it is empty and `result.next.waiting` is not, say nothing is ready yet and list each waiting story's key with the keys and statuses in its `blocked_by`; when both are empty, say the backlog has no TODO story left. Never pick or suggest a story yourself. Then run `node "${CLAUDE_PLUGIN_ROOT}/scripts/story-worktree.mjs" remove --key <story key>` and relay it: the worktree is removed, or it stays (with the reason) until its branch is pushed or merged — run the same command again then.
6. On `CONFLICT_ALREADY_COMPLETED` tell the user the story is already complete (never retry); on `FORBIDDEN_CLAIM` tell them they do not hold this story's lease (claim it first); on any other error report the code + request id and stop.
7. Make no further Hub calls for this step.
